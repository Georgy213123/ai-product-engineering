# Playwright MCP

Через Playwright MCP агент управляет настоящим браузером: открывает страницу, читает
доступное дерево (accessibility snapshot), кликает, вводит, смотрит консоль и сеть.
Мне он нужен для двух вещей:

1. **Приёмка.** Агент `e2e-acceptor` проходит критерии приёмки на стенде и приносит
   протокол с доказательствами, а не «вроде работает».
2. **Разведка перед тестом.** Прежде чем писать e2e, агент проходит сценарий руками
   и подбирает устойчивые локаторы по ролям. После этого тест пишется с первого раза.

## Подключение

`.mcp.json` в корне проекта:

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest", "--isolated", "--viewport-size", "1440,900"]
    }
  }
}
```

`--isolated` означает чистый профиль на каждую сессию: без чужих cookies и входов.
Если нужен вход, тестовую учётку берём из сида стенда, а не из личного браузера.

Включить в `.claude/settings.json`: `"enabledMcpjsonServers": ["playwright"]`.
Проверка: `/mcp` показывает `playwright · connected`.

## Как агент им пользуется

```
browser_navigate      → http://localhost:5101/inbox
browser_snapshot      → дерево ролей: ищем button "Сгенерировать черновик"
browser_click         → по ref из снапшота
browser_console_messages → ошибки после действия
browser_network_requests → ответы ≥ 400
browser_resize        → 390×844, повтор сценария
```

## Ограничения, о которых помню

- Снапшот большой страницы тратит много контекста. Длинные прогоны отдаю субагенту,
  чтобы страницы не попадали в основной контекст.
- Ширина 390 px в десктопном Chromium — не телефон: `@media (hover: none)` не срабатывает.
  Для мобильной приёмки нужен контекст с `hasTouch` и мобильным user agent.
- На продовом домене агент только читает. Формы с реальными последствиями
  (заказ, оплата, отправка) нажимает человек или тест на стенде.
