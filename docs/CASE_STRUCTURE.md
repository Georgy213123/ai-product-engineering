# Как устроен каждый кейс

Все три кейса собраны по одному канону. Читать можно с любого места, но порядок
папок повторяет путь задачи: от вопроса заказчика до релиза.

```
projects/NN-name/
├── README.md              ← кейс за 2 минуты: задача, решение, карта модулей, запуск, ссылки
├── Makefile               ← единый интерфейс: make up / dev / lint / test / e2e / audit
├── docker-compose.yml     ← весь стенд одной командой
├── backend/               ← FastAPI + PostgreSQL (у ShopProbe — бэкенд демо-витрины)
├── frontend/              ← React + TypeScript (Vite)
├── e2e/                   ← Playwright
└── docs/
    ├── 01-problem.md          постановка: боль, кто пользователь, что считаем успехом, границы
    ├── 02-analysis/
    │   ├── as-is.bpmn, to-be.bpmn   BPMN 2.0 (открываются в Camunda Modeler / bpmn.io)
    │   ├── processes.md             те же процессы в Mermaid — видно прямо на GitHub
    │   ├── use-cases.md             акторы, диаграмма и сценарии use case
    │   ├── requirements.md          FR / NFR с ID и приоритетом (MoSCoW)
    │   └── user-stories.md          истории с критериями приёмки (Given / When / Then)
    ├── 03-design/
    │   ├── architecture.md          C4: контекст и контейнеры (Mermaid)
    │   ├── er.md                    ER-диаграмма и словарь данных
    │   ├── openapi.yaml             контракт API (выгружается из кода, сверяется тестом)
    │   └── adr/NNNN-*.md            архитектурные решения (формат MADR)
    ├── 04-ai-development.md   декомпозиция на задачи для агентов, план → проверка другой моделью → код → ревью
    ├── 05-testing.md          стратегия (пирамида), что покрыто, отчёт прогона
    ├── 06-bugs.md             симптом → причина → исправление → регрессионный тест
    └── 07-releases.md         путь MVP → рабочая версия; CHANGELOG.md рядом
```

## Сквозные правила

- **Трассировка.** У требования есть ID (`FR-03`), история ссылается на требование,
  тест — на историю (`US-02` в имени или docstring). Матрица трассировки — в `05-testing.md`.
- **Контракт первым.** `openapi.yaml` лежит в репозитории; тест падает, если код
  разошёлся с контрактом.
- **Внешние сервисы — за адаптером.** Маркетплейс, LLM и учётная система подключены
  через интерфейс; в репозитории только заглушки, которые работают без ключей.
- **Демо, а не продукт.** README каждого кейса показывает полную карту модулей
  гипотетического продукта и честно помечает, какие из них реализованы в демо.
